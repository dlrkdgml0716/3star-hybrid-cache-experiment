# 실행 결과 보관

2026-10-09에 검증한 정상 부하 3회와 구독 중단 1회의 전체 실행 묶음을 `published/`에 보관합니다. 이는 현재 설계 이전의 기록입니다. 이전 실행과 실패한 실행은 Git에서 제외되는 `runs/`에 그대로 남겼습니다. 조건과 해석은 상위 [README](../README.md#이전-구현의-관측-기록-2026-10-09)를 확인하세요.

실험 도구는 `runs/<run-id>/manifest.json`과 원시 관측·로그·요약을 함께 저장합니다. manifest의 artifacts는 그 실행의 파일 목록과 SHA-256이며, 실제 파일 없이 결과를 주장하는 문서가 아닙니다.

공개할 실행은 검토 후 `published/<run-id>/`로 실행 묶음 전체를 복사합니다. 다른 실행의 원시 자료를 합치거나 수치를 수정하지 않습니다. manifest의 결과 파일 해시는 보존된 산출물 검증용이며, 소스 해시는 실행 당시 코드를 식별합니다. 과거 소스 해시가 현재 코드와 같다고 가정하지 않습니다. 각 실행의 `error-summary.json`은 당시 계측 범위의 두 인스턴스 Redis·listener·시계 오류 차이를 기록합니다.

2026-10-13 최신 설계의 기본 동작·실제 Redis 통합 테스트, 정상 부하 1회, 구독 중단 1회, 소규모 stale probe는
로컬 `runs/`에 별도 보존했습니다. 실행 ID와 결과는 상위 [최신 관측 결과](../README.md#최신-구현의-관측-결과-2026-10-13-로컬-검증)를 참고하세요.
최신 묶음은 아직 `published/`로 복사하지 않았으며, 일반적인 Git push에 포함되지 않습니다.

`verification/`은 설계 변경 단계별 단위·합성 검증과 관련 XML·해시를 보존합니다. 이전 기록을 최신 결과로 덮어쓰지 않습니다.
재적재 경쟁 방어의 근거와 부하 관측은 구분합니다. 변경 전후의 직렬화·메시지·호출 경로·계측이 달라,
과거와 최신 부하 수치의 차이를 성능 또는 stale 감소 효과로 해석하지 않습니다.

실행 환경은 Windows 호스트의 Docker Desktop(12 CPU·약 8 GiB 할당), 두 앱 컨테이너·MySQL 8.0·Redis 7, 호스트 k6 1.6.1입니다. 단일 로컬 PC의 결과이며 별도 호스트에서의 성능을 예측하지 않습니다. manifest의 소스 해시는 실행 시점 파일을 식별합니다.
