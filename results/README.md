# 실행 결과 보관

2026-10-09에 검증한 정상 부하 3회와 구독 중단 1회의 전체 실행 묶음을 `published/`에 보관합니다. 이전 실행과 실패한 실행은 Git에서 제외되는 `runs/`에 그대로 남겼습니다. 조건과 해석은 상위 [README](../README.md#관측-결과-2026-10-09)를 확인하세요.

실험 도구는 `runs/<run-id>/manifest.json`과 원시 관측·로그·요약을 함께 저장합니다. manifest의 artifacts는 그 실행의 파일 목록과 SHA-256이며, 실제 파일 없이 결과를 주장하는 문서가 아닙니다.

공개할 실행은 검토 후 `published/<run-id>/`로 실행 묶음 전체를 복사합니다. 다른 실행의 원시 자료를 합치거나 수치를 수정하지 않았습니다. 이번 네 실행의 manifest에 있는 결과 파일 해시와 현재 소스 파일 해시가 일치함을 확인했습니다. 각 실행의 `error-summary.json`에는 두 인스턴스의 Redis·listener·시계 오류 카운터 차이가 남습니다.

실행 환경은 Windows 호스트의 Docker Desktop(12 CPU·약 8 GiB 할당), 두 앱 컨테이너·MySQL 8.0·Redis 7, 호스트 k6 1.6.1입니다. 단일 로컬 PC의 결과이며 별도 호스트에서의 성능을 예측하지 않습니다. manifest의 소스 해시는 실행 시점 파일을 식별합니다.
